## PR6. Connector scaffold and direct-source normalization
- 这两天先把 `PR6` 的平台基础设施落稳。关键不是“加了两个平台名”，而是让 Xiaohongshu / Instagram 在 catalog normalization 和 QA verification 里有了明确 contract。
- 具体收口点包括：
  - `canonicalizeUrl(url): string | null`
  - 只承认 Xiaohongshu 的 `/explore/<postId>` 与 `/discovery/item/<postId>` 直链 surface
  - unsupported / search-like surface 不再被顺手升格成 `direct_source`
  - remote verification 只把这些 surface 当 QA 证据面，而不是 public product behavior
- 这让 Xiaohongshu 后续 seed prep 和 promotion 有了可验证的 URL 规范，而不是继续依赖一堆临时 share link 和 search link。

## Xiaohongshu candidate prep and QA review chain
- 在 connector 稳定之后，这两天单独做了 Xiaohongshu seed candidate follow-up，而不是把候选直接塞进 `contents.ts`。
- 目标创作者固定为 3 位：
  - `盖奥`
  - `灵熙🎾`
  - `冠军教练 - 莫拉托格鲁`
- QA-only 候选链的核心做法是：
  - 先确认 creator profile URL
  - 再从 `search_result/...` 入口拿 note-level candidate
  - 同时保留 `rawUrl`、解析后的 canonical `/explore/<postId>`、creator profile URL、thumbnail evidence、preliminary tags
  - 要求 `title === profileConfirmedTitle`，避免被盗号内容或同名内容混入
- 最终形成了两份 QA artifact：
  - `ops/quality/xiaohongshu-seed-candidates.json`
  - `ops/quality/xiaohongshu-seed-reviewed.json`
- 这两份文件的意义不在于“又多了 15 个视频”，而在于 repo 已经有了 profile-based candidate prep 和 manual review handoff 的固定路径。

## Small reviewed seed promotion

  - promotion 只发生在强 evidence 和人工确认都到位之后

## Cover stabilization and outbound behavior
- 这两天还把 Xiaohongshu 运行时最容易出问题的两件事一起收掉了：
  - 远程封面不稳定
  - 移动端点击先落到中间网页页
- 封面侧的最终方案不是继续赌 xhscdn 热链，而是：
  - 把 15 张已审定的封面本地化到 `public/thumbnails/xiaohongshu/`
  - 运行时直接走本地 thumbnail 路径
- 出站链路侧，则在移动端对 Xiaohongshu note 优先走：
  - `xhsdiscover://video_feed/<postId>`
  - 并保留 web canonical URL 作为 fallback
- 这样做的真实效果是：
  - library 卡片不再大面积出现灰底 placeholder
  - 手机端点击更像“打开 App 看 note”，而不是先掉进网页过渡页

## `/mobile-preview` workspace
- 这两天还补了一个非常实用的本地开发工作台：`/mobile-preview`。
- 它不是第二套页面，而是一个本地 mobile shell，用同源 iframe 直接加载真实的：
  - `/diagnose`
  - `/plan`
  - `/library`
  - `/profile`
- 这样本地开发时不需要每改一次就 push Vercel 才能看手机布局。后续对 `/library` 的移动端重排、双栏瀑布流和 note card 压缩，都是在这套 preview workspace 上迭代出来的。
- 今天后半段还继续校准了 preview shell 的宽度、内层 frame shell 和 `mobilePreview=1` 强制移动态，让 preview 更接近真机，而不是又多出一层把内容区压窄的开发外壳。

## `/library` mobile relayout and RedNote note feed
- 在 preview workspace 基础上，这两天把 `/library` 的移动端从“桌面筛选页塞进手机壳”进一步往“内容优先的 note feed”方向压。
- 当前触发规则保持非常窄：
  - 当前页是 `/library`
  - 当前是移动端或 `mobilePreview=1`
  - 平台筛选器明确选中 `Xiaohongshu`
- 只在这 3 个条件同时满足时，结果区才切到双栏瀑布流。
- 同时也做了几轮卡片层级压缩：
  - Xiaohongshu note 卡使用 `3:4` 竖版封面
  - 平台显示名中文为 `小红书`，英文为 `RedNote`
  - 盖奥 / 灵熙 的字幕标签统一成 `中文字幕`
  - 莫拉托格鲁统一成 `中英字幕`
  - 标题、meta chip、bookmark 位置都往更轻的 note-card 层级收
- 今天最后几轮微调则把问题重新落回两个最实在的地方：
  - card body 的真实 padding
  - thumbnail framing/crop 的统一策略
